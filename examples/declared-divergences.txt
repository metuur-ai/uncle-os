# Declared-divergence registry for examples/differential.py
#
# Task 0.6, acceptance R-7.1a. Read by the harness at startup; nothing here is
# optional decoration — every entry suppresses a real difference between the
# Python CLI and the Go port, and every entry must cite the requirement clause
# or exit-code-map line that sanctions it.
#
# ---------------------------------------------------------------- format ----
#
# Blank-line-separated records of `key: value`. `#` starts a comment line.
# A record is keyed by (invocation, stream[, step]); duplicates are rejected.
#
#   invocation  exact corpus id (`examples/differential.py <a> <b> --list`).
#               Globs are deliberately NOT supported: a glob that fires on 7 of
#               its 8 matches would look healthy while hiding one regression.
#   stream      stdout | stderr | exit_code | file_tree
#   step        optional 1-based step index; omitted = any step
#   authority   REQUIRED, non-empty, and validated against a shape:
#                 R-0.7a(<a-k>)                          — a sanctioned-difference clause
#                 R-<n>.<n>[a]                           — a requirement id
#                 .devlocal/go-port/exit-code-map.md:<n> — a classified die() site
#               Comma-separate multiple citations. An entry that cites nothing
#               is a hidden bug, so the harness refuses to load one.
#   reason      REQUIRED prose: what differs and why that is allowed.
#   expect      exit_code only, REQUIRED: `<reference> -> <candidate>`. Only that
#               exact transition is waived; any other pair is a hard DIVERGE.
#   waive       stdout/stderr/file_tree only, REQUIRED:
#                 whole-stream  the stream is not compared at all
#                 usage-block   (stdout/stderr) drop every line BEFORE the first
#                               `company-os...: error: ` line on both sides, then
#                               compare the remainder. This waives argparse's
#                               wrapped usage block per R-0.7a(i) while still
#                               comparing the diagnostic line R-1.4a requires.
#
# The harness fails on an undeclared divergence AND on a stale entry — one whose
# invocation ran and no longer diverges on that stream. Delete an entry the day
# its divergence is fixed; a stale waiver is how a fixed bug silently un-fixes
# itself later.
#
# NOT declared here, deliberately: divergences from commands the Go port has not
# implemented yet — `validate`, `governance`, `deviation`, `exception`, every one
# of which still dispatches to notImplemented() and exits 2. Those are unfinished
# work, not sanctioned differences; pre-declaring them would hide real defects
# when they land. The same rule applies to a multi-STEP invocation whose later
# step is one of those commands (`graph/build-then-validate`,
# `workspace/sync-then-validate`, …): waiving the chain would waive the
# implemented step with it.
#
# `prd`, `discover`, and `check` were on that list until task 2.6 landed them.
# Their sanctioned exit-code divergences are declared below, in the two sections
# marked "task 2.6". The measurement that produced those entries also answered
# the question the deliberate omission was there to protect: across the whole
# three-command cluster the ONLY non-exit-code difference is
# `discover/new-no-title`'s stderr, and that one is a Python traceback, not a
# defect in the port. Zero stdout differences, zero file_tree differences.

# ======================================================================

# bin/company-os:43) becomes the Unit 4 contract code. Each entry cites the
# classified die() site in the task-0.5 exit-code map.
# ======================================================================

# ======================================================================
# stdout — `--help`, and only the usage line's wrapping.
#
# R-0.7a(i) was widened to cover stdout as well as stderr because argparse writes
# `--help` to stdout. The clause waives argparse's COLUMNS-dependent WRAPPING and
# says the top-level usage line "legitimately differs in content because Go
# carries --json and --version flags Python does not have". It does not waive
# answering a different question, and this is worth stating because the port used
# to: every `company-os <sub> --help` printed the ROOT help, dropping the
# subcommand's own flags. That was a defect, not a divergence, and it was fixed
# rather than declared — `help(scope)` in cmd/company-os/main.go now renders the
# named sub-parser, reproducing argparse's section order, its metavars, its
# `help=` strings verbatim, and its `min(longest + 4, 24)` gutter.
#
# Measured after that fix, across all sixteen sub-parsers: eight are now
# BYTE-IDENTICAL to the oracle (validate, discover, governance, check, reality,
# scratchpad, graph, skills) and the other eight differ in the usage line's wrap
# and in nothing else. `usage/validate-help` therefore needs no entry at all —
# it PASSES — and only two invocations remain declared here.
#
# Both use `waive: whole-stream`, which is weaker than the `usage-block` mode the
# stderr entries above use, and the weakness is structural rather than a choice:
# usage-block anchors on the first `company-os...: error: ` line, and help output
# is not an error and has no such line, so the stripper would be a no-op on both
# sides and the comparison would be unchanged. Help stdout has no narrower mode.
# ======================================================================

invocation: usage/help
stream: stdout
waive: whole-stream
authority: R-0.7a(i)
reason: the TOP-LEVEL help, the one case (i) carves out by content and not only
  by layout — Go's root parser carries --json and --version, which the oracle has
  no equivalent for, so its usage line and its options block cannot match and the
  subcommand table is reformatted around them. Nothing here is a subcommand's
  own help; those are handled by help(scope) and eight of them are byte-identical.

invocation: usage/prd-help
stream: stdout
waive: whole-stream
authority: R-0.7a(i)
reason: `prd --help` differs from the oracle on ONE thing: argparse wraps
  `usage: company-os prd [-h] [--team TEAM] --platform PLATFORM …` across four
  lines at COLUMNS=80 and the port emits it on one. Everything below it — the
  `positional arguments:` and `options:` sections, their metavars, the
  `-h, --help  show this help message and exit` line and its 24-column gutter —
  is byte-identical. That single wrapped line is the exact difference (i) names,
  and it is unreproducible by design: a golden captured from it is a golden of
  $COLUMNS, which is not stable across CI runners.
